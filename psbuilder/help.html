How the builder works

Three mechanisms decide what comes out of a flow: variables put an answer into a sentence, repeat-per turns one task into many rows, and effort lines put hours against a task. They are easy to mix up, so each one is set out separately below.
01Variables

A variable is a question you write once and then refer to by name inside any task description. Wrap its token in braces — {agent-training} — and the answer is substituted when the estimate is generated.

Agent training (desktop, call/chat handling, wrap-up codes) — {agent-training} sessions answer 4 → Agent training (desktop, call/chat handling, wrap-up codes) — 4 sessions

This stays one task and one row. The number only changes the wording.

In the task form, the chips under Description insert these for you. If a token matches no variable it is left in the text exactly as written, so {tpyo} reaches the spreadsheet as {tpyo} — the builder will not warn you, though the task importer does.

02Line numbers, and repeating a task

This one is different: it makes a single task come out as several rows. Set Repeat per on the task to a number variable, and it emits one row per unit. Inside the description, {#} becomes the row number.

Workshop {#} — discovery session repeat per {workshops} answer 3 → Workshop 1 — discovery session Workshop 2 — discovery session Workshop 3 — discovery session

Each row carries the full hours of the task. That is the whole point of repeating rather than mentioning: three workshops cost three workshops.

{#} on a task with no repeat set is left literal. Only number variables can drive a repeat. The cap is 200 rows per task — ask for more and you get 200 plus a notice saying what was clamped.

These stack, and that is the easiest way to double-count: a task repeating per {workshops} and scaling its hours per {workshops} multiplies. Pick one.

03Hours

Open a task and find Who does the work, and for how long, then press + Add resource. Each resource line is four things:

FieldWhat it is
RoleThe engineer doing the work
LocationWhere they do it
Business hoursHours in normal time, in 0.25 steps
After hoursHours out of hours, in 0.25 steps

Add a line per role if a task needs more than one. A task with no resource lines reads "No effort costed against this task yet" and contributes nothing.

Hours that scale

Under each hours field is + Scale with a variable, which gives you a base plus a rate:

Business hours 2 plus 0.5 per agent-domains 6 domains → 2 + (6 × 0.5) = 5 hours

Only number variables can be scaled against, and only linearly — there are no tiers or thresholds. If pricing needs a step change, make it a separate task with a condition.

04Getting it into the PSE

The builder gives you two blocks to copy rather than one, because pasting a single wide block over the sheet would overwrite the columns it calculates from — the round trips, stays and document counts.

BlockPaste atHolds
1 · Task details A Phase, skill required, task type, description
2 · Resource hours J Five resource slots — location, business hours, after hours each

The sheet fixes one role per resource column on row 41, not per row, so the builder assigns each role you have used to a slot and tells you which slot got which role. There are only five columns: use more than five distinct roles in one subflow and you get a notice naming the ones that will not fit.

Paste both blocks at the same row. Block 2 is generated in the same order as block 1, so the two line up only if they start level.
