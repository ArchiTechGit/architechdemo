How the builder works

A flow is one kind of engagement. A subflow is a variation of it — a new build against a migration, say — and a task can belong to one subflow, several, or all of them. A flow can have no subflows at all, in which case it has a single shape and every task is in it. Everything below is about the tasks.
Putting hours on a task

Open a task and the first panel is Who does the work, and for how long. Press + Add resource and set four things: the role, whether it happens in the office or on site, and the hours split between normal time and after hours.

FieldWhat goes in it
RoleThe engineer doing the work
LocationWhere they do it
Business hoursHours in normal time, in quarter-hour steps
After hoursHours outside normal time, in quarter-hour steps

Add a resource per role if a task needs more than one. The figure at the top right of the panel is the running total for one line of output, so you can watch it as you type. A task with no resources contributes nothing and says so.

When the hours depend on an answer

Under each hours box is + Scale with a variable. That gives you a fixed amount plus a rate per unit:

Business hours 2 plus 0.5 per agent-domains 6 domains → 2 + (6 × 0.5) = 5 hours

Only questions that produce a number can be scaled against, and only in a straight line — there are no tiers or minimums. If the price steps at a threshold, make it a second task and put a condition on it.

Using an answer in the task text

A variable is a question you write once and can then refer to by name anywhere in a task description. Put its name in braces and the answer replaces it when the estimate is generated. The chips under the description will insert one for you.

Agent training — {agent-training} sessions answer 4 → Agent training — 4 sessions

This is one task and one row. The answer only changes the wording, not the hours.

A name that matches no variable is left exactly as typed, so {tpyo} reaches the spreadsheet as {tpyo}. The builder will not warn you about that, though the task importer does.

Getting several rows from one task

This is the one people mix up with the last one. In the hours panel, set How many lines to One line per… a number variable. The task then comes out once per unit, and {#} in the description becomes the row number.

Workshop {#} — discovery session How many lines: one line per workshops answer 3 → Workshop 1 — discovery session Workshop 2 — discovery session Workshop 3 — discovery session

Every row carries the full hours of the task. That is the whole difference: three workshops cost three workshops, where the training example above costs one.

{#} in a task set to Just one line stays as written. The limit is 200 rows from one task — ask for more and you get 200 and a notice saying so.

Doing both multiplies. A task set to one line per {workshops} whose hours also scale per {workshops} costs the square of what you meant. Pick one.
Putting the tasks in order

Rows come out in the order the tasks are listed, so the order is worth getting right — it is what the estimate reads like top to bottom. Drag a task by the grip on its left, or focus it and hold Alt with the up and down arrows.

A task only moves among the rows shown beside it. Moving something inside All subflows cannot disturb the order of a subflow you are not looking at.

Getting it into the PSE

The builder gives you two blocks to copy rather than one, because a single wide block would paste over the columns the sheet works out for itself — the round trips, the overnight stays and the document counts.

Copy thisPaste at columnIt holds
1 · Task details A Phase, skill required, task type, description
2 · Resource hours J Five resource slots — location, normal hours, after hours each

Start both at the same row. The second block is built in the same order as the first, so they only line up if they begin level.

The sheet holds the role for each resource column on row 41, once, rather than on every row — so the builder picks a column per role and tells you which went where. There are only five columns. Use more than five roles across one subflow and you get a notice naming the ones that will not fit.

Reading an existing sheet in

Import in the toolbar takes a copy straight out of a PSE and turns it into tasks. Select the task rows and copy the full width — not just the four description columns — and the hours come with them.

The columns are read by position, which is safe because the sheet fixes their order: four task columns, then the three counts, then the two effort columns, and then the resource columns in groups of three.

Phase Skill Task type Description · · · R1 loc R1 hrs R1 after R2 loc R2 hrs R2 after each further group of three is another resource

One thing the paste cannot tell you is whose hours those are. The sheet keeps the role for each resource column on row 41, once, rather than on every row. So the panel asks, and describes what each column holds — 10.5h across 3 tasks · Office — which is usually enough to recognise whose column it was.

Until every column with hours has an answer, the button will not add anything. Guessing would put the hours against the wrong engineer and quietly change the price. If you do want the tasks without their hours, that is the last option in the list rather than something that happens because you did not notice the question.

Rows already in the flow arrive unticked, so pasting the same sheet twice does not double it. Blank rows are ignored.

Moving a flow, and keeping a backup

Export / import in the toolbar writes the flow you are looking at to a file, and reads one back. There is also a whole-config export, which is the one to keep as a backup.

A flow on its own would not be enough. It names a vertical, and its tasks name phases, skills, task types and roles that all live outside the flow — so a file carries those alongside it, and an import checks every one against this config before it changes anything.

Skills, task types, roles and verticals that are missing get added for you, and the panel says which. Phases and locations do not: they are the columns of the spreadsheet, so a file cannot introduce one. If a flow needs a phase this config has not got, you are told, and nothing is imported until it is sorted out.

If a flow with the same id is already here you choose between keeping both — the incoming one is renamed — and replacing what is there. Either way nothing reaches GitHub until you press Save, and the same validation that guards a normal save guards this.

Light and dark

Light in the header switches theme, and the choice is remembered on that browser. Dark is the default because it is the theme the ArchiTech brand specifies.

The light theme is not the dark one inverted. Cyan reads at 2:1 on a pale ground, which no label or link can use, so on light the interactive colour becomes ArchiTech Blue — which is the role the brand gives it. The phase edges move to darker blues for the same reason. Every colour in both themes is checked against WCAG AA on the build.
